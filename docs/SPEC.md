# MODX: модуль «Планировки»

Техническое задание и руководство по разработке. Версия 1.0, 14 октября 2026 года.

Документ объединяет согласованные требования и проектные предложения для реализации. Разработка модуля и изменения сайта на момент подготовки документа не выполнены. Рабочее техническое имя — `PlanPoint`, пространство настроек — `planpoint`; эти имена предлагаются, а не являются существующими компонентами сайта.

## 1. Цель и границы

Создать модуль MODX для подготовки интерактивных схем этажей прямо в менеджере: выбор изображения, обводка помещений, установка номеров и SVG-точек для пинов, повторное использование схем, назначение этажам и вывод через чанк.

Основной сценарий: открыть ресурс дома → вкладку «Планировки» → добавить или редактировать схему → сохранить → назначить одному или нескольким этажам. Сайт получает схему по ID ресурса этажа.

Первая версия включает визуальный редактор для ПК, импорт SVG, окно полного кода схемы, копирование внутри дома и в другой дом, массовые назначения, информационный блок на этаже, документацию и устанавливаемый транспортный пакет.

Обработка изображений, автоматическая обводка, автоматическое исправление импортированных идентификаторов, самостоятельная генерация квартир, финансовые функции и переработка фильтра каталога в задачу не входят. Отдельные команды «Скачать SVG» и «Экспорт SVG» не требуются; копирование полного кода предусмотрено.

## 2. Что установлено по текущему сайту

Основание: присланные пользователем Fenom-шаблоны и локальные файлы `app.min.js`, `app.min.js.map`. Карта содержит читаемый источник `app.js`. Диагностика выполнена по файлам, без проверки на работающем сайте.

| Участок | Текущее поведение |
| --- | --- |
| Общий блок каталога | Подключает фильтры, `plan_v.1.tpl` и результаты квартир |
| `plan_v.1.tpl` | Меню этажей, подключение `svg.tpl`, компас |
| Меню | Переходы по ссылкам на ресурсы; этажи имеют шаблон 8 в предоставленном коде |
| `svg.tpl` | Читает JSON TV `plan` текущего ресурса, выводит изображение, `$item.svg`, улицы и HTML-пины |
| `msProducts` | Выводит квартиры текущего этажа с шаблоном 4; формирует `.pin-item` |
| Ключ HTML-пина | `x{$section}-{$layout_code_custom ?: $layout_code}` |
| `mFilter2` | Вывод и фильтрация квартир; не является хранилищем схем |
| JavaScript | Связывает контуры, пины и карточки по ключу; показывает карточки и назначает статусы |

Шаблоны 8 и 4 — факты конкретного присланного кода, не универсальные значения для установки модуля. ID шаблона дома и подъезда, версия MODX, PHP и библиотек менеджера пока не установлены.

Выбор этажа в рассмотренном сценарии меняет страницу. Поэтому ID текущего ресурса подходит для получения схемы и квартир. Сниппет дополнительно принимает явный ID этажа для других сценариев.

Сейчас MIGX допускает несколько записей на одном этаже. В новом модуле у этажа одна назначенная схема. Существующие MIGX-данные не удалять и автоматически не переносить. После подключения нового вывода возврата к MIGX при отсутствии назначения нет: показывается заглушка.

## 3. Термины и структура ресурсов

- Дом — ресурс, к которому принадлежат схемы.
- Подъезд/секция — необязательный промежуточный ресурс; также так называется необязательное поле схемы для формирования ключей. Само назначение этажам не меняет это поле.
- Этаж — ресурс, которому назначена схема.
- Схема — изображение, контуры, SVG-точки и свойства, используемые одним или несколькими этажами.
- Область — один замкнутый контур помещения. Несколько областей могут иметь один номер и ключ.
- Пин схемы — SVG-точка `circle[data-pin]`. HTML-пин квартиры создаёт сайт, а не редактор.

Поддерживаемые иерархии: дом → подъезд → этаж и дом → этаж. Поиск ограничен потомками текущего дома и настроенными шаблонами. Не включать этажи вложенного другого дома. Для первой версии не предполагать произвольную глубину структуры; нестандартные структуры диагностировать и описывать отдельно.

## 4. Интерфейс менеджера

### 4.1. Вкладка дома

Вкладка «Планировки» появляется только у ресурсов с настроенными шаблонами домов. Шаблоны выбираются из списка по названию, сохраняются их ID. Новый несохранённый ресурс сначала необходимо сохранить, чтобы получить ID.

Основной экран — таблица схем текущего дома: миниатюра, название, назначенные подъезды/этажи. Поле «Подъезд/Секция» отдельной колонкой не показывать. Действия: добавить, редактировать, назначить этажам, копировать, удалить; выбор нескольких схем для копирования в другой дом.

Использовать штатные компоненты и стили менеджера MODX для таблиц, вкладок, полей, кнопок, окон, уведомлений и дерева. Собственное оформление ограничить холстом и инструментами редактора. Конкретный способ регистрации вкладки выбрать после проверки версии MODX, не менять ядро.

### 4.2. Создание и редактор

При создании: название, изображение, поле «Подъезд/Секция», переключатель SVG-меток. Далее открывается редактор. Назначения можно настроить позже.

Поле «Подъезд/Секция»: текст, по умолчанию пустое. Подсказка: «Необязательно. Например: 2». Сотрудник не вводит служебную букву `x`. Рядом допустим предпросмотр итогового ключа.

Редактор открывается в обычном размере; доступны увеличение и возврат к обычному размеру. Не разворачивать автоматически. Инструменты над холстом, свойства выбранной области справа. Кнопки: «К списку», «Сохранить», «Новая область», «Импорт SVG», «Код схемы», изменение размера редактора.

Минимальные функции холста: масштабирование, перемещение обзора, создание контура, выбор области, перемещение/добавление/удаление вершин, удаление области, изменение номера, установка и перемещение SVG-точки. Предлагается локальная история отмены/повтора до закрытия редактора. Скругление, показанное в раннем макете, не считать окончательно специфицированным: до реализации отдельно определить управление радиусом и представление в геометрии; кривые импортировать без потери при поддержке редактором.

### 4.3. Обводка и номера

В режиме новой области клики добавляют вершины в координатах исходного изображения. Контур замыкается кликом по первой вершине, минимум три вершины. При приближении первая вершина подсвечивается; экранный радиус захвата не зависит от масштаба.

После замыкания область остаётся выделенной. Пользователь правит номер, вершины и метку. Следующая область начинается кнопкой «Новая область» или N. Горячие клавиши не срабатывают при вводе в поле или редакторе кода.

Номер хранится как текст: `6`, `06`, `106`, `6А`. При создании автоматически предлагается очередной свободный числовой номер `1, 2, 3…`; вручную можно повторить существующий или ввести другой допустимый номер. Не приводить `06` к числу 6. Для новых ключей допускаются цифры и буквы; неподходящие для действующих селекторов символы отклонять с объяснением. Импорт не исправляет ключи автоматически.

Новые ключи: пустое поле секции + номер `6` → `x-6`; секция `2` + номер `06` → `x2-06`. Один префикс применяется ко всем новым областям схемы. Изменение поля у уже заполненной схемы должно показывать затронутые ключи и требовать явного применения. Для импортированных ключей не выполнять молчаливую перенумерацию.

Разрешены несколько контуров с одним ключом. Для такого ключа хранится одна точка. При присвоении существующего номера использовать существующую точку, не создавать дубликат; интерфейс должен объяснять общую метку. При изменении номера одного из нескольких контуров оставить точку у оставшейся группы и при включённых метках создать точку новой группы. При удалении последнего контура предложить удаление его точки; не уничтожать вручную импортированные независимые точки молча.

### 4.4. SVG-точки

В редакторе маркер заметный и удобный для перетаскивания. В результирующем коде точка маленькая: по умолчанию `r="0.4"`, `cx` и `cy` — в координатах изображения. Размер экранного маркера редактора не переносить в SVG.

После создания области при включённых метках автоматически поставить точку внутри области; для вогнутой фигуры не использовать без проверки обычный центр ограничивающего прямоугольника. При повторном ключе сохраняется общая точка. Пользователь может её переместить вручную.

Переключатель меток управляет выводом точек; предложенное правило хранения — выключение не удаляет уже размещённые координаты, чтобы их можно было вернуть. Поведение явно пояснить в интерфейсе.

### 4.5. Частичная готовность и сохранение

Можно сохранять и назначать схему без контуров, с одной областью или с любым количеством готовых областей. Полная обводка не является условием назначения.

Сохранение явное, кнопкой. Если схема используется, перед сохранением показать затронутые этажи и запросить подтверждение. При уходе с изменениями предупредить. Автосохранение и восстановление черновика первой версией не требуются.

При незамкнутом контуре предложить вернуться к обводке либо отбросить только незавершённый контур и сохранить готовые данные. Не терять контур без выбора пользователя. При ошибке сервера данные редактора остаются на экране.

## 5. Изображения

Форматы загрузки подложки: PNG, JPG/JPEG. Загрузить с компьютера или выбрать существующий файл в источнике MODX. Обработку, обрезку, оптимизацию, создание WebP и изменение прозрачности модуль не выполняет. PNG сохраняет прозрачность.

Источник файлов и отдельная папка схем задаются в настройках. Схема хранит ссылку и сведения, необходимые для однозначной работы через источник, а не содержимое изображения. Размеры проверяются по содержимому файла. Для новой схемы `viewBox="0 0 W H"`, где W/H — исходные размеры подложки.

При замене изображения геометрия и точки остаются на прежних координатах. При отличии размеров показать старые и новые размеры и предупредить; не масштабировать разметку автоматически. Предложенное поведение: после подтверждения обновить viewBox до новых размеров, сохранив координаты; показать возможные выходы за границы.

Копии используют ту же ссылку, без дублирования файла. Изменение ссылки у копии не меняет исходную схему. Перезапись самого общего файла через файловый менеджер может затронуть все ссылающиеся схемы — предупреждать в операциях модуля, где это известно.

Импорт SVG относится к разметке, а не к разрешению загружать SVG как новую подложку. Текущий сайт умеет отображать SVG-файлы подложки, но новая загрузка в первой версии ограничена согласованными растровыми форматами.

## 6. Назначение этажам

Окно «Назначить этажам» показывает только этажи текущего дома: дерево подъездов и этажей либо список этажей без подъездов. Шаблоны берутся из настроек. Названия показываются из ресурсов; номер этажа для диапазонов извлекать из согласованного поля, предложено `menutitle`, с проверкой числового значения. Не угадывать диапазон по ID ресурса.

Доступны галочки отдельных этажей, выбор всего подъезда и числового диапазона. Повторное открытие показывает существующие назначения схемы; снятие галочки снимает её назначение. У этажа только одна схема.

При конфликте показать текущую и новую схемы, список этажей и явный выбор замены или отмены. Диапазоны 2–10 и 10–15 пересекаются на этаже 10. Не заменять назначение молча. Не снимать назначения другой схемы при снятии галочки с этажа, который за время работы окна уже был переназначен.

Назначение допустимо только схеме того же дома. Проверка выполняется сервером заново при сохранении. Пакетное назначение атомарно: либо подтверждённые изменения применяются целиком, либо возвращается ошибка без частичного результата.

На ресурсе этажа показывать информационный блок: название схемы, миниатюра, «Посмотреть», «Изменить назначение». При отсутствии — «Схема не выбрана». Выбор ограничен схемами текущего дома, меняет только этот этаж.

На телефоне доступны просмотр и переназначение этажей. Обводка и редактирование вершин ориентированы на ПК.

## 7. Копирование и удаление

Копирование сохраняет изображение-ссылку, геометрию, номера, точки, настройки вывода и свойства. Назначения очищаются; название начинается с «Копия …». Поддержать копирование выбранной группы схем в другой доступный дом. Проверку/изменение поля «Подъезд/Секция» предложить явно; не менять импортированные ключи автоматически.

Удаление схемы разрешено и при назначениях: показать название, число и перечень этажей, подтвердить удаление схемы, её данных и назначений. После удаления эти этажи получают заглушку.

Изображение удалить вместе со схемой только если оно управляется модулем, находится в разрешённой папке выбранного источника, не используется другими схемами и пользователь видит это действие в подтверждении. При общих ссылках файл сохраняется; показать число и названия использующих схем. Файл вне управляемой папки/недоступный для удаления сохраняется с объяснением.

Проверка модуля гарантирует только собственные ссылки. Не обещать выявлять использование в произвольных чанках, TV, CSS, JS и внешних системах. В подтверждении одиночного файла написать, что внешние ссылки автоматически не проверяются. Удаление файла не должно нарушать другие схемы; перед операцией повторить проверку ссылок. Если удаление файла не удалось после удаления записи, сообщить «Схема удалена, файл сохранён» и записать ошибку.

## 8. Импорт и полный код

Поддержать загрузку `.svg` и вставку кода. Импорт заменяет контуры и точки целиком после подтверждения. Для обычного SVG-импорта подложка, свойства и назначения сохраняются. Идентификаторы, порядок, координаты и геометрию автоматически не исправлять.

При отличии viewBox от изображения показать предупреждение с размерами и началом координат. Не выполнять автоматическое растяжение. После явного подтверждения поддержанный импорт сохраняет исходный viewBox; для нового рисования в такой схеме использовать именно его координатную систему. Если редактор не поддерживает такое сопоставление, отклонить применение с причиной, а не менять данные.

Окно «Код схемы» содержит полный блок: обёртка `.plan-svg`, изображение, SVG-контуры и `circle[data-pin]`. HTML-пины квартир, улицы и компас в переносимый код схемы не включаются. Доступны просмотр, ручное редактирование, «Применить изменения» и «Копировать код».

Применение полного кода отличается от импорта SVG: оно может менять ссылку изображения и поддержанные свойства разметки, что показывается до применения. Назначения этажам сохраняются. Новая ссылка должна разрешаться и проверяться; произвольное скачивание сервером по внешнему URL не требуется.

Перед применением — синтаксическая, структурная и серверная проверка. При неподдерживаемых конструкциях показать конкретную причину и оставить прежнюю схему. Код не упрощать молча. Сохранять исходную строку импорта и возвращать её без изменений при отсутствии редактирования. После визуальной правки допустима пересериализация только затронутых геометрических данных, без потери поддержанных атрибутов и структуры.

Предлагаемый минимум совместимости: SVG `path` с прямыми и кривыми, `circle[data-pin]`, классы и `data-i`, viewBox. Команды пути M/L/H/V/C/S/Q/T/A/Z в обоих регистрах либо поддерживаются без геометрических потерь, либо конкретный неподдержанный путь полностью отклоняется. Группы, transform, стили, маски, clipPath, use и иные конструкции включать только при корректном обратимом отображении. Нельзя принимать сложный SVG, а затем терять его при сохранении. Матрицу поддержки закрепить в README и тестах.

Скрипты, обработчики событий, foreignObject, активные URL, внешние сущности и опасные вложения не исполнять. Отклонять весь импорт с уведомлением, а не скрытно удалять элементы. Импортированный код не выполнять как MODX/Fenom-шаблон. Превью строить только после проверки.

## 9. Контракт фронтенда

```html
<div class="plan-svg">
  <picture>
    <img src="/assets/plans/floor.png" alt="Типовая схема" class="plan-svg__img">
  </picture>
  <svg class="plan-svg__svg" viewBox="0 0 1800 840" xmlns="http://www.w3.org/2000/svg">
    <path class="path-item" data-i="x-6" d="M 100 100 H 300 V 300 H 100 Z" />
    <circle data-pin="x-6" cx="200" cy="200" r="0.4" />
  </svg>
  <!-- Улицы и HTML-пины добавляются чанкoм сайта, не хранятся в схеме -->
</div>
```

| Элемент | Связь |
| --- | --- |
| Контур | `.path-item[data-i="x-6"]` |
| SVG-точка | `circle[data-pin="x-6"]` |
| HTML-пин | `.pin-item[data-i="x-6"]` |
| Карточка результата | `id="x-6"`, `data-href`, класс `booked` при наличии |

По изученному JS: наведение на контур/пин показывает карточку по ID; класс `hover` назначается всем элементам с тем же `data-i`; `booked` карточки приводит к `--lock`; отсутствие `data-href` приводит к `--sold`. На ПК клик ведёт по `data-href`, на малом экране открывает карточку.

Точное совпадение ключа обязательно. Старый импорт `x1--6` сохраняется, но не сопоставится с `x1-6` без подготовки данных. Модуль может показать диагностическое предупреждение, но не исправляет импорт.

HTML-пины и статусы остаются ответственностью сайта. Область без соответствующей квартиры не удалять. Отсутствие карточки сейчас приводит к состоянию `--sold`; это поведение учитывать при частичных данных и фильтрации.

### 9.1. Позиционирование пинов

Текущий `pin_center()` использует `.offset()` SVG-элемента и размеры ближайшей `.plan-svg`, запускается через 300 мс. Это положение ограничивающего прямоугольника, а не гарантированно центр SVG-точки. Кроме того, селектор назначения стилей глобальный и может затронуть другую схему с тем же ключом.

В отдельной правке интеграции вычислять экранный центр `cx/cy` через преобразование SVG в экранные координаты, затем координаты внутри фактического позиционирующего контейнера пина. Учесть CSS padding/border, масштаб и трансформации. Искать `.pin-item` только внутри текущего блока. Не полагаться на размер SVG-круга.

Пересчёт: после загрузки изображения, для уже загруженного изображения сразу, при изменении размеров контейнера, после показа скрытого блока. Ограничить повторные вычисления кадрами. Не подключать второй конкурирующий обработчик поверх `pin_center()` — заменить или согласованно отключить старый вызов.

В `mse2_load` рассмотренного кода отсутствует повторное обновление статусов планировки. Если результаты меняют доступные карточки, согласованно обновить статусы и привязки после загрузки; не считать отсутствие карточки из-за фильтра доказательством продажи. Правило отображения отфильтрованных квартир проверить на сайте отдельно; это интеграционный вопрос, не изменение хранилища схем.

## 10. Вывод через сниппет и чанк

Предложенное имя сниппета `PlanPointRender`. Это будущий API, а не уже установленный сниппет.

| Параметр | Назначение |
| --- | --- |
| `floorId` | ID этажа; по умолчанию текущий ресурс |
| `tpl` | Чанк результата, по умолчанию `PlanPointScheme` |
| `tplEmpty` | Чанк заглушки, по умолчанию `PlanPointEmpty` |

Сниппет получает назначение, схему и изображение, выводит чанк. Не извлекает квартиры и не добавляет зависимость от miniShop2/pdoTools в универсальное ядро. Эти компоненты нужны только адаптеру конкретного сайта. Недоступный ресурс/файл и повреждённые данные обрабатывать без PHP-ошибок на странице, с журналом для администратора.

Предложенные плейсхолдеры: `scheme_id`, `house_id`, `floor_id`, `title`, `image_url`, `image_width`, `image_height`, `viewbox`, `svg`. В документации различать исходные значения и безопасные значения для HTML-атрибутов; title/URL экранировать, SVG выводить только после проверки. Файловые чанки поддерживать через отдельный проверенный адаптер, не обещать `@FILE` стандартному обработчику MODX без реализации.

Пример будущего вызова из Fenom:

```smarty
{$_modx->runSnippet('PlanPointRender', [
    'floorId' => $_modx->resource.id,
    'tpl' => 'PlanPointSchemeSite',
    'tplEmpty' => 'PlanPointEmpty'
])}
```

Пример обычного вызова:

```text
[[!PlanPointRender? &tpl=`PlanPointSchemeSite` &tplEmpty=`PlanPointEmpty`]]
```

При подключении заменить содержимое `svg.tpl` вызовом сниппета. Адаптированный чанк `PlanPointSchemeSite` включает единственную обёртку `.plan-svg`, изображение, SVG, существующие улицы и вызов `msProducts` для HTML-пинов. Исключить двойную вложенную `.plan-svg`.

Сохранить исходный `msProducts`: `parents` текущего этажа, шаблон квартир 4 для данного сайта, `limit=0` и существующее формирование ключа. Если явно задан `floorId`, в адаптере использовать его и для квартир/улиц, а не оставлять текущий ресурс.

При отсутствии назначения заглушка: `.plan-svg` и текст «Схема скоро появится». Назначенная схема без контуров показывает изображение, а не заглушку. Решение по HTML-пинам без SVG-точек: не показывать неразмещённые пины в случайном месте; адаптер скрывает их до успешного позиционирования.

Компас и улицы сейчас предполагают двухуровневую структуру родителей. Для варианта без подъезда адаптер должен определять дом и секцию по шаблонам и принадлежности, а не неизменно брать parent.parent. Сохранить порядок наследования: сначала секция, затем дом. Общий шаблон и меню не перестраивать.

## 11. Хранение и архитектура — предложение реализации

Отдельные таблицы модуля. Назначения не хранить большим общим TV/MIGX. Изображения — в источнике MODX.

Чтобы импорт не терял сложную поддержанную разметку, предлагается хранить каноническое проверенное SVG и редактируемую модель вместе в записи схемы. Отдельные таблицы каждой вершины не обязательны. Документ схемы обновляется атомарно; модель и SVG не могут сохраняться раздельно.

| Таблица с префиксом MODX | Основные поля |
| --- | --- |
| `planpoint_schemes` | id, house_id, context_key, title, section, image_ref_id, viewbox, show_pins, geometry_json, svg_code, imported_source, schema_version, revision, created/updated_by, created/updated_at |
| `planpoint_images` | id, media_source_id, source_path, public_url/cache, width, height, managed, created_at |
| `planpoint_assignments` | floor_id, scheme_id, revision, updated_by, updated_at |

Изображение идентифицировать по источнику и нормализованному пути, а не только URL. URL может меняться; строковая ссылка хранится для вывода/диагностики, но операции выполняются через источник. Общие ссылки на один объект должны давать общий image_ref_id.

Ограничения: уникальное назначение по floor_id; индекс scheme.house_id; индекс assignment.scheme_id; уникальность ссылки изображения по source/path; UTF-8 для названий и номеров. Контекст ресурсного дерева проверять при копировании и назначении. Конкретные SQL-типы и xPDO-схему определить после проверки среды, не требовать новых возможностей СУБД без необходимости.

Модель `geometry_json`: стабильный внутренний ID области, номер как строка, ключ как строка, данные пути/вершин; отдельная коллекция точек по ключу. Импортированные произвольные ключи хранятся как исходные строки, без обязательного разложения на секцию/номер. Поле revision используется для контроля одновременных правок; schema_version — для миграций формата.

Рекомендуемые сервисы: ресурсная иерархия, CRUD схем, импорт/проверка/сериализация, изображения, назначения, рендер. Менеджер не обращается к БД напрямую. Общие правила проверяет сервер независимо от UI.

Согласованное правило: функции схем доступны всем пользователям менеджера, которым разрешён просмотр соответствующего дома; отдельного ограничения удаления только администратором нет. Доступ к файлам остаётся ограничен полномочиями источника MODX; если действие запрещено источником, объяснять причину.

Защита: запросы только аутентифицированной сессии менеджера, защита от CSRF принятым в среде механизмом, параметризованные операции, ограничение путей папкой, проверка действительного типа изображения, запрет активного SVG и исполнения кода импорта. Не позволять по подставленному ID читать/назначать схемы другого недоступного дома.

## 13. Предложенный контракт операций

Имена ниже — ориентир для разработки процессоров, не готовые endpoint.

| Операция | Данные и результат |
| --- | --- |
| schemes/list | house_id → схемы и назначения |
| schemes/get | scheme_id → свойства, модель, SVG, revision |
| schemes/save | данные + expected_revision → сохранённая схема и новая revision |
| schemes/copy | scheme_ids, target_house_id → новые схемы без назначений |
| schemes/remove | scheme_id, expected_revision, подтверждение → удаление и статус файла |
| assignments/tree | house_id → доступные этажи и назначения |
| assignments/apply | scheme_id, выбранные этажи, подтверждённые замены, версии → итог |
| assignments/set-floor | floor_id, scheme_id/null, версия → назначение одного этажа |
| images/upload/select | источник/файл → нормализованная ссылка и размеры |
| code/validate | код, режим SVG/полный блок → ошибки/предупреждения и модель без сохранения |

Ошибки должны различать: validation, access_denied, not_found, revision_conflict, assignment_conflict, unsupported_svg, image_unavailable. Формат привести к стандартному ответу менеджера установленной версии MODX.

При конфликте revision не перезаписывать чужие изменения. Предложить обновить схему, сохранив локальные данные для копирования/сравнения. Обновление назначений и удаление проверять на сервере после подтверждения UI.

## 14. Кеш, жизненный цикл ресурсов и ошибки

При сохранении схемы/назначений сбрасывать кеш рендера затронутых этажей. Самый простой первый вариант — некешируемый вызов сниппета; всё равно проверить кеш страницы/Fenom и необходимость очистки кеша ресурсов.

Удаление ресурса этажа очищает его назначение. Восстановление ресурса не должно автоматически назначать уже удалённую схему. При переносе этажа в другой дом прежнее назначение становится недопустимым: снять его с уведомлением/журналом. При удалении или изменении шаблона дома не уничтожать схемы и изображения автоматически; сохранить данные и исключить недопустимые назначения из вывода.

Точные события MODX и способ сопровождения ресурсов выбрать по установленной версии. Не зависеть только от физического удаления, поскольку ресурсы могут помечаться удалёнными.

## 15. План разработки

### Этап 0. Проверить среду

Зафиксировать версию MODX, PHP, СУБД, xPDO, менеджера, Fenom/pdoTools и источника файлов; ID шаблонов и реальную структуру. Получить CSS блока и чанк карточки квартиры для проверки позиционирования/ключей. Не спрашивать повторно уже присланные файлы. Сделать резервную копию изменяемых шаблонов и БД перед установкой на сайт.

Результат: паспорт среды, выбранная совместимость, матрица SVG и список точек подключения. Отсутствие этих сведений не мешает разработать изолированную модель/прототип, но не позволяет заявлять совместимость транспортного пакета с конкретным сайтом.

### Этап 1. Каркас и хранение

Настройки, модели/миграции, сервис проверки иерархии и доступа, процессоры CRUD, контроль ревизий. Транспортная установка повторяема; обновления сохраняют пользовательские данные.

### Этап 2. Менеджер и изображения

Вкладка домов, таблица, создание схемы, выбор/загрузка подложки, информационный блок этажа. Проверить стандартное оформление на установленной версии менеджера.

### Этап 3. Редактор

Координатная система, масштаб/панорама, замыкание, вершины, номера, повторные ключи, точки, частичное сохранение, предупреждения, изменение размера окна. Не смешивать редактор с DOM действующего сайта.

### Этап 4. Код и импорт

Parser/validator, обратимая модель, SVG без изменения ключей, предупреждения размеров, полный код, применение/копирование. Проверить реальный SVG пользователя, а не только искусственный прямоугольник.

### Этап 5. Назначения и операции

Дерево текущего дома, диапазоны/конфликты, копирование групп, удаление с общими файлами, мобильный просмотр/назначение.

### Этап 6. Рендер и адаптер сайта

Сниппет, базовые чанки, пример Fenom, адаптация `svg.tpl`, сохранение `msProducts`, улиц и компаса. Отдельная адресная правка JS позиционирования в исходнике с пересборкой штатным способом; не редактировать минифицированный файл вручную как основной исходник.

### Этап 7. Проверка и поставка

Проверить установку/обновление на тестовой копии, пройти критерии ниже, собрать transport.zip, исходники и документацию. Подключение на рабочем сайте — после проверки на копии и в пределах отдельного разрешения на изменения сайта.

Предложенная структура проекта: `core/components/planpoint/` для модели, сервисов, процессоров и элементов; `assets/components/planpoint/` для JS/CSS менеджера; `_build/` для сборки; `docs/` и `tests/`. Точные пути адаптировать к принятой структуре проекта.

## 16. Критерии приёмки

| № | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| 1 | Дом с настроенным шаблоном / другой ресурс | Вкладка есть только у дома |
| 2 | Дом с подъездом и без него | В назначения попадают только его этажи |
| 3 | Загрузка PNG/JPG и выбор существующего | Ссылка и исходные размеры корректны, прозрачность сохранена |
| 4 | Замыкание по первой точке | Минимум три вершины, область остаётся выделенной |
| 5 | Номер 06 и секция 2 | `x2-06`, ведущий ноль сохранён |
| 6 | Два контура с одним номером | Общий ключ и одна SVG-точка |
| 7 | Схема без контуров/с одной областью | Сохраняется и назначается |
| 8 | Незамкнутый контур при сохранении | Явный выбор, готовые области не теряются |
| 9 | Замена картинки другого размера | Предупреждение; координаты остаются прежними |
| 10 | Импорт старых ключей/кривых | Ключи и геометрия сохранены или импорт отклонён с причиной |
| 11 | Неподдержанный/опасный SVG | Не исполняется, прежние данные остаются |
| 12 | Импорт поверх схемы | Контуры/точки заменены после подтверждения; назначения сохранены |
| 13 | Копия схемы/группы в другой дом | «Копия …», общий файл, нет назначений |
| 14 | Диапазоны 2–10 и 10–15 | Конфликт 10-го этажа показан до замены |
| 15 | Удаление общей картинки | Схема/назначения удалены, общий файл остаётся |
| 16 | Назначение снято | Заглушка, без возврата к MIGX |
| 17 | Ключи контура, точки, пина и карточки | Подсветка, клик и карточка работают как прежде |
| 18 | Медленная загрузка/resize/скрытый блок | Пины оказываются на центре точек |
| 19 | Два блока с одинаковым ключом | Позиционирование не затрагивает соседний блок |
| 20 | Параллельные правки | Конфликт показан, чужие данные не перезаписаны |
| 21 | Подмена house/floor/scheme ID | Недоступные и чужие связи отклонены сервером |
| 22 | Обновление пакета | Схемы, изображения и назначения сохранены |
| 23 | Телефон | Просмотр/переназначение доступны; обводка не требуется |

Автоматические проверки оправданы для сериализации SVG, валидации, конфликтов назначений, принадлежности ресурсов, прав и миграций. Визуально проверить холст на разных масштабах, прозрачную подложку, существующую схему и совпадение пинов с CSS сайта. Не ограничиваться тестами, повторяющими реализацию.

## 17. Руководство пользователя и подключение — состав поставки

Поставить README установки, руководство сотрудника, руководство интегратора, список поддержанных SVG-конструкций, описание ошибок и инструкцию обновления/отката. Документация с реальными именами установленного пакета заменяет предложенные имена этого документа.

Инструкция сотрудника: открыть дом → «Планировки» → добавить название/картинку → обвести область → замкнуть → поправить номер/точку → «Новая область» → сохранить → назначить этажам. Для продолжения открыть ту же схему. Для готового SVG использовать импорт; для ручных изменений — «Код схемы».

Инструкция интегратора: установить пакет → выбрать шаблоны/источник/папку → создать и назначить тестовую схему → скопировать базовый чанк в чанк сайта → перенести существующие улицы и HTML-пины → заменить вывод внутри `svg.tpl` → проверить JS/стили и карточки → проверить кеш → подключить остальные этажи.

Откат вывода: вернуть резервную копию `svg.tpl` и исходной JS-сборки. Исходные MIGX TV остаются на месте. Это позволяет вернуть старый вывод, но новые схемы не конвертируются обратно в MIGX автоматически. Удаление пакета по умолчанию должно сохранять данные/изображения; полное удаление данных — отдельное явное действие.

## 18. Что остаётся проверить, не меняя согласованный объём

1. Реальная версия и зависимости MODX, PHP и менеджера.
2. ID шаблонов домов/подъездов, источника файлов, поле числового номера этажа.
3. CSS `.plan-svg`, SVG и HTML-пинов; чанк карточки с ID, booked и data-href.
4. Реальные SVG: используемые команды, группы и transform; границы поддержки без потери.
5. Штатная сборка JS и совпадение карты исходников с актуальным исходником проекта.
6. Поведение статусов после фильтрации квартир: скрытие и продажа должны различаться.
7. Детали инструмента скругления из макета, если его включают в первую версию.

Эти пункты — проверки среды и явно отмеченные детали реализации, не повод заново обсуждать весь интерфейс. Все согласованные решения выше сохраняются. Документ можно передать разработчику как основу проекта и использовать как чек-лист приёмки.

## Уточнения интерфейса от 14.10.2026

Согласованы компактные инструменты с подсказками, поля выбранного контура без кнопок применения, отдельные вкладки изображения/кода, нижняя строка управления. При рисовании видна линия до курсора и превью заливки. Enter не замыкает контур. После замыкания по первой точке остаётся непрерывный режим рисования со следующим номером. Esc отменяет текущий контур, затем возвращает выделение.
