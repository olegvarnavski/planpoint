# Исправления по аудиту, 0.3.0-alpha

## Данные редактора

История Undo/Redo хранит viewBox и метаданные изображения вместе с геометрией. После восстановления синхронизируются изображение, превью и пропорции холста. При визуальном изменении экспорт удаляет старые width/height импортированного SVG; текущий viewBox остаётся источником размеров.

Секция с дефисом разбирается по известному полному префиксу схемы, а не по первому дефису. Числовые/строковые значения show_pins нормализуются. Контуры с совпадающими или полностью коллинеарными вершинами отклоняются; самопересечения автоматически не исправляются. Строгая проверка площади применяется к сохранению/импорту. Публичный вывод старых схем допускает прежнюю геометрию, сохраняя все проверки безопасности SVG, чтобы обновление не скрывало уже опубликованную схему.

## Изображения

Сохранение передаёт и проверяет `image_source` вместе с путём. Если старый клиент не передал источник и путь изображения не меняется, используется сохранённый источник схемы. Смена настройки TV не подменяет файл на одноимённый из другого источника. Права источника и реальные размеры проверяются сервером повторно.

## Повторные запросы

Создание и копирование из менеджера получают случайный ключ запроса. Повтор с тем же ключом и теми же данными возвращает те же схемы; другой payload с прежним ключом отклоняется. Ключи разделены по пользователям. Проверка и создание результата проходят под существующей транзакционной блокировкой.

Старые клиенты без ключа остаются совместимыми, но не получают гарантию идемпотентности. Таблица requests хранит только операцию, хеш данных и ID результатов, не SVG/пароли/полную форму. Записи пока не удаляются автоматически: политика срока хранения должна учитывать окно безопасного повторения запросов. Если схема уже удалена, повтор старого ключа не создаёт её заново.

## Установка

Добавлены таблицы `{prefix}planpoint_requests` и `{prefix}planpoint_meta`. Версия схемы — 2. Исходные таблицы и назначения не пересоздаются. SQL-результаты проверяются, проверяются необходимые поля и InnoDB. Неполная старая таблица не исправляется разрушительным DROP/CREATE — установка сообщает ошибку. Это проверка состояния и добавочная миграция, а не универсальный ремонт повреждённой БД.

Validator проверяет версию платформы, PHP, DOM, mbstring, ctype, PDO и PDO MySQL. Результаты beginTransaction/commit контролируются. Ошибки PlanPoint не должны прерывать редактирование неподходящих ресурсов; инициализация плагина ограничена и защищена обработчиком исключений.

## API и скорость

Проверяются обязательные параметры, типы ID и JSON. Неожиданные исключения получают код запроса; журнал содержит операцию, пользователя и схему без записи полного payload. Сбой очистки кеша отражается неблокирующим сообщением; причина сохранения изображения после удаления схемы также видна пользователю.

Список не передаёт все SVG и исходные image_json: назначения и подписи загружаются группами. Открытие редактора/просмотра получает полный объект отдельным запросом. Публичный рендер не строит подписи всех назначенных этажей.

## Сохранённые ограничения

Права просмотра дома по-прежнему дают доступ к работе со схемами, как было согласовано; новые операции ACL не вводятся молча. Глобальная блокировка записи сохранена ради целостности общих изображений. При массовом назначении принадлежность этажей повторно проверяется внутри операции, однако транзакция PlanPoint не блокирует штатное перемещение ресурсов MODX другими запросами. Автоматическая очистка устаревших назначений, потерянных загрузок и записей requests остаётся отдельным этапом. Формат контуров и работа квартир/фильтра не меняются.
