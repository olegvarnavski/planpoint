# Файловая интеграция без дополнительных чанков (0.2.1)

В текущем `chunks/catalog/plan/svg.tpl` вызов:

```smarty
{set $scheme = $_modx->runSnippet('PlanPointRender', [
    'floorId' => $_modx->resource.id,
    'inner' => 1
])}
```

`$scheme` — только picture + svg. Без назначения — пустая строка. В существующем условии проверять `$scheme | trim`, вместо foreach по TV plan вывести `{$scheme}`. Существующие plan-street и msProducts остаются внутри одной обёртки .plan-svg, меню и фильтр без изменений. Обычные tpl/tplEmpty не нужны. Стандартный режим без inner сохраняет совместимость с 0.2.0.

Ключи контуров и SVG-точек должны точно совпадать с ключами пинов/карточек квартир, включая секцию, дефисы и начальные нули. Включить SVG-точки у схемы. Сначала можно проверить существующий app.min.js; он уже использует data-i/data-pin. Не подключать дополнительный pins.integration.js одновременно со старым pin_center(). Статусы брони/продажи читаются текущим JS из карточек квартир, их вывод сохраняется.

Обновление с planpoint 0.2.0 обычное, данные сохраняются. Старый planeditor — другое техническое имя, автоматического переноса из него нет.
